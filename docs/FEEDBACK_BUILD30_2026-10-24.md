# 0.7.9：Android build30 / Windows build31，五项手机反馈

## 差异与方案

1. 应用来源切换重建整个页面；图片后台解码仍持有词条仓库锁，长图解码/缓存偏大。保持页面与未改变的卡片，立即提交筛选；仅可见图片启动解码，长图只取顶部区域，预览独立取图。图片读取不再阻塞词条元数据的全局锁。缩略图请求合并，预览和收录分开队列。
2. 图片侧滑按钮随长图拉高，挤占双栏。两处图片卡片仅保留单击预览与长按菜单；文字侧滑维持原功能。
3. 应用来源栏、悬浮来源栏与分类栏统一滚动规则：左侧首屏可完整容纳的选择回到起始位置；溢出选择居中并钳制到内容边界。
4. 实机检查：Windows 正在运行 build29；手机文件服务与 Windows 日志确认蓝牙协商 catalog=true，电脑已收到手机的一条目录。手机没有 WLAN IPv4，Windows 在校园 WLAN。目录更新/打开文件页原先不会主动唤醒短连接，离线下载立即失败；页面还保留“蓝牙仅文字”的旧提示。新版本导入/打开文件页主动请求已授权连接，离线下载等待新目录并重新校验版本。蓝牙会话到三分钟时若正在传文件则延后关闭，LAN 升级不切断活动文件。另实测截图显示设备页直接发送失败：Windows 旧的直接发送适配器仍拒绝蓝牙请求；本轮统一允许协商了文件能力的蓝牙会话，接收仍须用户确认。
5. 长按与短筛选用紧凑锚定菜单，文件详情使用底部面板，删除/清理仍用确认框；共用主题、强调色、状态和热区。去掉系统默认的大弹窗入场动画。

## 范围

继续原生 Android、WPF/XAML、现有认证与协议，不改配对身份，不自动开启 Wi-Fi/热点/系统蓝牙或改代理。自动连接关闭时仍尊重该设置。LAN 优先；蓝牙按需续接。Wi-Fi Direct 尚无独立的发现/建组实现，不能把同一 Wi-Fi 或热点称为 Wi-Fi Direct。
