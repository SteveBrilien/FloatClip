# FloatClip 产品重整方案

2026-10-20 · 提案 1 · 待评审，尚未实现

## 产品定位

FloatClip 是一个可以在不同应用、不同设备间继续使用的浮窗剪贴板。用户在原来的应用里复制，在需要的位置直接选取、粘贴；打开 FloatClip 主要是整理历史和管理设备。

最重要的体验是：不用依赖 vivo 输入法的历史剪贴板，也不用把复制粘贴重新做成一次聊天或文件发送。

**本地使用不设账号门槛。** 按用户 04:35 的补充，Android / Windows 安装后直接进入剪贴板；本机功能和局域网组网均无需注册、网页登录、登录令牌或公网节点。首次添加设备只做设备身份核对并记住授权。公网 PWA 的访问保护单独保留，不能再成为原生应用启动、本机使用或本地配对的前置条件。

0.6.0 没有完成这一目标。本轮先确定产品与验收标准，暂停功能拼接和新安装包发布。现有部署保持可用，不自动回滚、卸载或改动用户数据。应用图标沿用 0.4.0 共享版。

## 复盘：0.6.0 为什么不合格

| 已出现的问题 | 对日常使用的影响 | 本次取舍 |
| --- | --- | --- |
| 网页主界面与原生“本机工具”并排存在 | 同一个剪贴板要在两个界面间往返 | 原生客户端只保留一套产品入口和数据操作 |
| 把共享设计成输入文字、发送、收件箱 | 已经复制的内容还要重新粘贴并发送 | 以剪贴板变更驱动同步，移除常驻文字编辑器和聊天式收件箱 |
| 配对只维持短会话，回到前台可能重来 | 每次使用都要先建立连接 | 首次授权后记住设备；网络连接可以重建，授权关系不随断线消失 |
| 主界面四个栏目、大卡片、重复说明 | 找内容之前先理解功能结构 | 一个剪贴板主界面；设备与设置为次级页面 |
| 本机管理和本地组网也依赖网页加载与认证入口 | 使用本地工具也先登录，断网或节点不可用影响基本操作 | 原生本机功能与局域网组网都不依赖账号、网页和公网节点；公网 PWA 保护单独处理 |
| 将三端外观复用当成功能统一 | 浏览器限制反过来限制了原生体验 | 共用产品语义和协议，按平台实现原生能力 |
| 以构建、自动测试通过代替产品验收 | 技术可以运行，却不一定方便 | 每次交付必须走完真实复制粘贴任务，再做反向批判 |

## 核心流程

### 在手机上使用

1. 在原来的应用中复制文字，FloatClip 在获得相应系统能力时收进本机历史。
2. 在另一个应用点浮窗，直接看到最近条目。
3. 点条目直接粘贴；当前输入框不支持一键粘贴时，明确显示“已复制”，由用户使用系统粘贴。不能把复制成功显示为粘贴成功。

默认点选后收回；固定模式下保留浮窗，方便连续粘贴多个条目。不抢输入焦点、不让键盘异常收起。长按或更多按钮提供置顶、分类、删除等操作，默认页面不铺满操作按钮。

浮窗初始约显示四至六条，按可用屏幕空间调整；完整历史可以继续滚动，搜索按需展开，不靠缩小字体硬塞更多条目。

### 在手机与电脑间接续

1. 首次添加设备并核对身份，用户明确开启两台设备间的剪贴板同步。
2. 在手机正常复制；已授权、在线的电脑自动收到新的剪贴板事件，不要求打开发送页。
3. 电脑可直接粘贴当前接续内容，也可从历史中选择。反向同理。

历史收录与系统当前剪贴板接力要分开控制：开启同步时先说明会共享新复制的文字，并提供暂停；不会默认上传整个旧库。关闭自动接力后，远端内容只进入历史，不覆盖本机当前剪贴板。

### 在 iPad PWA 中使用

使用相同的剪贴板、来源设备和记录操作。向外提供内容时点“加入剪贴板”并完成浏览器粘贴授权；收到内容后点一下复制，再回原应用粘贴。PWA 是目前 iPad 的前台接入端，不承诺后台监听、锁屏自动送达或系统浮窗。

## 界面与交互

| 界面 | 正常状态下保留什么 | 不在这里出现什么 |
| --- | --- | --- |
| 手机主界面 | 紧凑标题、搜索、来源切换、剪贴板条目；右上进入设备和设置 | 大品牌横幅、发送文字框、重复状态卡、四栏底部导航 |
| 浮窗 | 少量最近条目、固定开关、必要的来源切换 | 配对操作、传输方式选择、大段权限说明 |
| 我的设备 | 设备名称、授权/在线状态、同步开关、添加与撤销 | 每次使用都要生成的临时房间、要求用户判断协议 |
| 设置 | 浮窗与粘贴、外观、同步与隐私、数据与备份 | 旧版工具跳转、兼容模式的第二套产品界面 |

来源设备沿用用户之前的分区需求，用“全部 / 本机 / 电脑 / iPad”等轻量切换显示同一套记录，不另造多个收件箱。同名设备按稳定身份区分；来源是最初产生内容的设备，转发不会反复改变来源。

文字是列表的主体。默认两行预览，只有远端条目显示简短来源；置顶只用小标记，时间为次级信息。分类放在筛选和条目菜单内，不与设备来源叠出两排常驻导航。长内容按需查看全文。

沿用 0.4.0 图标与蓝白方向，统一浅色、深色、系统跟随的排版和反馈。图标源为 nearby-probe/src/main/res/drawable/ic_floatclip.xml；实施时复制该资产，不重新绘制品牌。

Windows 以托盘和快捷键调出剪贴板为日常入口，主窗口用于整理。iPad 在宽屏上可以显示选中内容的详情，但保留相同操作含义；不要求三个平台使用相同导航布局或同一网页外壳。

## 系统能力是第一道验收门槛

代码复盘发现：当前无障碍服务仍通过普通 ClipboardManager 读取并缓存文字；浮窗采集只在面板打开时尝试。它不能证明已经具备全天候后台剪贴板历史采集。

Android 官方说明，Android 10 及以上，普通应用在没有当前焦点且不是默认输入法时受到剪贴板读取限制。因此先在用户的 Android 11 / OriginOS 上验证已授权的 ADB / Shizuku 受控桥方案；单纯开启悬浮窗或无障碍不能作为成功依据。Shizuku 能启动也不等于该 ROM 的剪贴板访问一定可用。

这一步的成功条件是：在其他应用中连续复制、FloatClip 不在前台且浮窗未展开时，仍能正确收录；期间不抢焦点、不收起键盘、不要求换输入法。重启、锁屏与权限失效后的边界必须实测并明确显示。若这一步失败，先向用户报告能力与替代方案，不能用手动发送流程宣称完成系统剪贴板。

Windows 采用系统剪贴板变更通知，避免高频读取。iPad Safari 的剪贴板读写需要用户操作等浏览器条件，单独按前台使用验收。

## 同步如何成为剪贴板的一部分

- 设备授权长期保存、可撤销；临时网络会话断开时自动恢复，取消人为的十分钟产品使用上限。后台维持方式需服从系统限制并测量耗电，不以高频轮询维持“在线”。
- 主界面只显示连接是否可用，网络路径自动选择。局域网可达时优先直连；校园网隔离或直连不可用时，在允许使用节点的前提下回退。不能把经公网节点传输写成局域网直传。
- 每次复制具有稳定事件 ID、原始设备身份和源设备序号。接收后写入系统剪贴板不会生成一条新的本机同步事件，避免 A → B → A 回环；不只依赖文字相同来去重。
- 收到历史与替换“当前剪贴板”分别处理。两端同时复制时保存两个事件；无法确定因果先后时不覆盖本机新复制内容，也不能仅靠设备时钟排序解决冲突。
- 离线后重连先恢复可用状态。过期的接力事件不重新覆盖系统剪贴板，未同步内容保留在发送端本机，明确可重试；先不引入无限远端历史镜像。
- 同步可以一键暂停，条目可以设为仅本机。支持平台明确标记的敏感内容排除；不承诺能准确识别所有密码或验证码。

首次配对可以扫码或输入短码，核对后完成授权。后续不用反复粘贴链接。扫码权限只在实际选择扫码时请求。

局域网配对由两端在本地完成身份交换和密钥确认，不调用公网账户接口。配对码是短时的首次确认材料，设备信任关系持久保存。没有网页账号的设备也能互认；网络被校园 AP 隔离属于链路不可达，账号登录不能解决这种隔离。公网节点只作为另外授权启用的可选通道；跨网路径仍需保护，但不会变成全 App 的登录墙。

## 保留、收起与暂缓

| 保留为核心 | 收进次级操作 | 暂缓 |
| --- | --- | --- |
| 浮窗剪贴板、稳定采集与粘贴、历史检索、置顶、分类、设备来源、可信设备接续 | 备份迁移、传文件、连接诊断、版本更新 | 蓝牙/Wi-Fi Direct 研究、图片复制粘贴增强、复杂历史全量同步、更多主题 |

文件通过系统分享、拖入或条目菜单进入同一任务流程，不占一个主页面。文本剪贴板闭环稳定后再恢复文件增强，不删现有用户数据。

旧 FCP2/FCS1 传输代码可以复用或适配；不在正式界面保留第二套“兼容模式”应用。确实需要诊断时进入独立诊断工具。协议差异由适配与明确的版本提示处理。

## 实施顺序与退出条件

1. **先验证核心系统能力。** 在受控测试内容下验证 Android 11 采集、焦点和粘贴，记录哪些情形有效。手机不可用时只准备方案和测试，不碰用户正在使用的设备。
2. **再做单机完整 App。** 统一主界面、浮窗、设置和一份本机库，取消主界面对网页与账号的依赖。保留当前共享版的包名和固定签名。旧版记录以“预览 → 合并导入 → 可恢复”迁移，不把原生恢复的覆盖行为带入新方案。
3. **打通手机与 Windows 接续。** 首次授权后持续使用，验证系统剪贴板事件、持久授权、重连、冲突与去重。不能只验证浏览器之间能发一段文字。
4. **接入 iPad 前台流程并统一视觉。** 同一个记录模型与设备身份，不承诺浏览器没有的系统能力。
5. **完成批判性验收再发候选版。** 先审核实际任务录屏和失败情形，再给安装包；不按新增入口或代码量判断完成。

## 发布前必须能回答的批判

| 问题 | 通过标准 |
| --- | --- |
| 正在其他应用打字，取旧条目是否顺手？ | 点浮窗、点条目即可完成受支持的粘贴；不用进主 App，键盘与输入焦点正常 |
| 断网或小主机离线，本机功能还能用吗？ | 采集、浮窗、历史和本机备份不受账号或网页加载阻塞 |
| 两台原生设备在可互通的局域网中，没有账号且公网不可用，能首次配对吗？ | 清洁安装、不登录账户、阻断公网节点后，仍能完成本地设备核对、配对和剪贴板接续 |
| 在手机复制后，电脑还要发一遍消息吗？ | 开启同步并在线时无需打开应用或点击发送；正常局域网文本接力目标为两秒内，作为实测门槛，不是现有成绩 |
| 下次打开是不是又要配对？ | 既有授权保留；断线恢复不要求重新抄链接，撤销后才重新授权 |
| 同步会不会覆盖我刚复制的内容？ | 并发冲突保留双份历史，当前剪贴板不被过期或不确定先后的远端内容覆盖 |
| 多台设备会不会出现重复内容轰炸？ | 多端转发和重试保持同一事件身份，不形成回环，也不重复建档 |
| 普通用户是否需要看懂网络协议？ | 默认路径由软件选择；诊断属于按需查看的信息 |
| iPad 是否被宣传成能后台接管系统剪贴板？ | 所有相关入口与说明明确是前台点按流程，锁屏状态不显示虚假的持续在线 |
| 视觉是否比 0.4.0 更省事？ | 日常主界面没有发送框、旧工具入口和重复状态卡；浮窗条目可单手点选，放大字体不裁切 |
| 长时间运行会不会影响手机？ | 与关闭应用的同设备基线对照待机、唤醒和流量，给出实测；当前不预设“低功耗已达成” |

任何核心流程不通过时，回到该流程修改；不能用增加一个开关、另一个页面或一段解释来代替解决问题。

## 方案自身还未解决的风险

- “本机剪贴板 + 跨设备接续”仍可能过大。按单机、双原生端、PWA 三段交付，先证明每段可用。
- 连接状态长期占着浮窗会造成噪声。正常在线只用轻量状态，故障才给可操作提示，不让网络错误遮住本机历史。
- 默认自动接力可能打断本机复制意图。将历史接收、当前剪贴板接力分开；首次授权明确选择，后续可随时暂停。
- 分来源与分类同时展示会重新变复杂。只常驻来源切换，分类按需筛选；小屏以四个以内的来源入口为上限，其余进入选择列表。
- 更换技术框架并不会自动解决产品问题。实施时以原生数据与交互闭环为依据选用组件，不为统一代码牺牲平台能力。
