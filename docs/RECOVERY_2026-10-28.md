# Android build33 恢复候选（2026-10-28）

## 用户回归与已知边界

用户实测 build32 出现：操作后悬浮窗/悬浮球消失、启动短暂白屏、关闭剪贴板时闪退、更新检查经常失效且体验不好。build32 的自动测试没有覆盖用户设备上的实际窗口合成和完整可见/触摸状态，不能凭78项通过宣称可用。build32 暂停推荐；旧包保留作取证，不覆盖。

手机 Termux Remote 在连接 mcp.desktopcommander.app/api/mcp-info 时失败，Node 返回 ECONNRESET：TLS 建立前 socket 被断开。还未进入设备注册；deviceId undefined 是后果。目前无正式 ADB，不能认定已取得/复现手机崩溃栈，也不能把具体线程或 API 认作已证实的唯一根因。服务器侧该API已测HTTP200，不能替代手机同路测试。

## 最小恢复改动

- 撤回 build32 的跨窗口球→面板位移/缩放/圆角转场。保留 build31 的固定大小原生窗口与复用方式，展开/收回立即提交可见、缩放和触摸状态；不再靠动画结束回调恢复球。保留按需列表、后台快照和位置选项，暂停新增动效。
- 服务统一持有窗口登记，移除采用 removeViewImmediate。停止后拒绝晚到的 add/update；活动窗口被系统先行移除时仅尝试一次恢复。销毁时先标记 stopping、停止后台回调、取消动作再卸载窗口；只处理已知窗口/权限异常，不吞掉其他程序错误。
- 冷启动关闭默认系统预览，声明随系统亮暗的启动底色；在 onCreate 初始阶段应用实际外观底色。首次 onResume 不再重复创建整个剪贴板页；共享启动放到首轮页面构建后。
- 更新检查改成单一请求、可见进度、可取消、12秒界面截止时间、失败重试与来源状态。显示两个来源失败原因，保留上次成功检查记录并标清时间；失败不称为最新。销毁Activity即取消请求并关闭窗口，晚到结果不能弹窗。保留原RS256公钥、验签、下载域名、包名与签名验证策略。
- 未加入新的应用内安装器；下载仍使用现有系统浏览器入口。正式预览/开发源仍为已签名build29，签名有效至2027-01-21，未把恢复候选冒充正式更新。原发布私钥在目前离线Windows设备上。
