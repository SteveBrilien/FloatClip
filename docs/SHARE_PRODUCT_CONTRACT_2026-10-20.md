# FloatClip 0.6.0：三端统一产品与发布规范

## 产品与导航

Android、Windows、iPad PWA 共用 0.6.0 共享界面和 web-v1 传输流程。主入口统一为“剪贴板、共享、设备、设置”；窄屏底栏、平板和桌面侧栏。继续采用蓝白 / 深色 / 跟随系统。

剪贴板包含搜索、分类、置顶、复制、合并导入导出、再次发送；以设备安装或浏览器配置中的稳定 ID 区分来源，不以设备名称作主键。名称相同的设备仍可分开，名称变化不拆分板块。浏览器与原生应用是独立客户端，可能出现在不同板块；不采集硬件唯一标识。

设备来源用于记录内容从哪一个端收到，不代表该端已经获得永久信任。每次共享仍需配对及识别码核对。

## 存储与原生适配

- Android 升级对象为当前共享版 com.floatclip.probe，versionCode 12，沿用 0.4.0 固定签名（036859…）。源码命名空间仍为 com.floatclip.app，整合其 Android Keystore 加密库、分类、置顶、悬浮球、无障碍粘贴、加密备份和本机管理页面。原版 com.floatclip.app 可并存，原版历史需通过便携加密备份手动恢复；无来源的旧记录归为本机。签名私有权限使用安装包名作用域，避免与原版重复声明。
- Windows 使用 WPF + Microsoft WebView2 宿主；共享入口复用上述界面与协议，本机记录使用 DPAPI 当前用户保护。缺少 WebView2 或网络时提供本机剪贴板、局域网兼容模式和官方组件安装入口。
- PWA 使用 IndexedDB 和不可导出的 Web Crypto 密钥保存加密库。仅在先前登录仍有效且认证请求发生网络故障时，允许访问本机缓存；服务器返回未授权时必须回到登录页，离线标记不提供服务器授权。
- 跨端复制的 JSON 备份含明文；原版手机的 PIN 加密备份入口继续保留。服务端不接收或保存整个剪贴板库。接收文字默认保存到本机，可以关闭；文件仍需主动接收和选择保存位置。
- 主库采用版本比对写入，合并最新数据后再提交，避免悬浮球与共享页面或多个窗口互相覆盖。读取损坏库时不以空库覆盖原文件；用户明确恢复备份是独立操作。

宿主只向 https://clip.wmy-cloud.cn 的受信页面提供有限本机操作，禁用通用主机对象和任意路径访问。Android 系统文件选择器与 Windows 保存对话框负责授权文件位置。公共网页本身不具备手机悬浮窗或静默后台剪贴板读取权限。

## 协议和兼容性

共用传输保留 WebRTC 与经小主机的加密中继。设备 ID / 平台通过已加密的数据通道传递，hello 版本维持 1、元数据可选，旧 PWA 可继续交换内容；旧端没有稳定标识时以临时会话来源显示。

旧版原生 FCP2/FCS1 LAN 模式保留在“局域网兼容模式”，与主共享界面分开。本轮覆盖同包名、同签名的旧 Share；原版 FloatClip 与其不同包名，不会被覆盖，也不能跨应用沙箱自动读取其私有数据。备份迁移先保留一份副本，新旧应用不要使用同一个自动备份目录。

PWA 不能主动建立蓝牙 / Wi-Fi Direct / AirDrop 链路；Android/Windows 的这些硬件路线仍待独立实测。背景静默同步、永久配对与自动重连未纳入 0.6.0。校园网隔离时默认节点模式仍使用公网，不会因本轮整合自动变为局域网路径。

## 同步发布

所有端的目标版本统一写在 web/public/release.json；Android Gradle、Windows 项目与宿主版本、Web 包及后端版本须一致。scripts/check-share-contract.py 检查这些字段、能力声明、存储适配、宿主入口和共享配色。

变更共用功能时修改同一共享代码并验证三端适配；涉及宿主 API 时同步升级安装包。网页更新检查同时显示相应平台的安装包下载，避免只更新网页后漏掉原生宿主更新。

先通过测试，再冻结 APK/ZIP，取得不可变下载地址，更新安装包 SHA256 / 大小与网页发布信息后部署。已发布版本字节不得覆盖；内容变化须提高版本或构建号。`distribution` 独立记录是否真正可下载。Android 发布必须验证 updates/android-identity.json 中当前 Share 的证书、包名、版本及私有权限；不再要求原版独立应用的签名。缺少固定密钥时发行失败，不生成新密钥冒充同一升级线。CI 临时签名只供构建验证，不作为已发布包。

## 验证边界

协议级和本地存储测试不替代真机验收。未获得测试窗口时不操作手机 ADB，不扫描或改动 OrangePi 连接测力设备的有线网络。iPad Safari 安装 / 布局、原生宿主与文件选择器、真实 Win10/Win11 的 WebView2 和 DPAPI 仍需硬件验证。
