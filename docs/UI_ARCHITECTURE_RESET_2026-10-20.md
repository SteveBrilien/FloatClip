## 1. 本次结论

0.7.1 并未完成产品界面整合。复用了多套有独立主题、导航、控件工厂和生命周期的界面；版本号一致、部分样式检查通过，不能证明它们构成了一套产品。白底白字属于阻断发版的可读性缺陷。

目标仍是：以手机系统浮窗剪贴板为核心，把本机历史、跨设备历史和设备管理放进一个连贯的应用。主界面找内容，浮窗取用内容，设备页管理连接。保留 0.4.0 应用图标、蓝白主色、深色 / 浅色 / 跟随系统及此前确认的单击、左滑、撤销、按压交互。

本机与原生局域网使用无需账号；公网节点访问保护保留。网络问题不能阻断本机历史和浮窗。本轮推进已授权设备的后台连接接续，不承诺绕过系统的后台剪贴板权限；蓝牙与 Wi-Fi Direct 不在本轮实施范围。

## 2. 代码审计与证据

| 位置 | 当前实现 | 直接问题 |
| --- | --- | --- |
| Android MainActivity | Kotlin 程序化 View；1385 行，页面、控件、数据操作与导航集中 | 主界面 / 设置单独维护 AppColors；整页重建依赖手动保存输入状态 |
| Android 设备页 | DeviceActivity 继承旧 ShareActivity，使用 ShareDesign | 主题读取 share-ui/theme；主界面读取 floatclip_overlay/theme_mode，偏好和色板均独立 |
| Android 浮窗 | ClipboardOverlayService + WindowManager + AdaptiveOverlayThemeProvider | 使用第三套表面色与圆角来源，并可能读取 OEM 资源；与主界面缺少统一组件契约 |
| Windows 工程 | C#、net10.0-windows、WPF；WinForms 用于托盘；可选 WebView2 | 目前以窗口类和事件处理为主，尚非整理好的 MVVM 架构 |
| Windows 本机页 | LocalClipboardWindow 程序化创建控件 | Button 设置了画刷但未统一 ControlTemplate；ComboBox / CheckBox 等保留默认模板；设置、设备分别开其他窗口 |
| Windows 旧共享页 | App.cs 内嵌 XAML 字符串和另一套 Resources | 旧页按钮圆角 10、卡片 18；新页又有 13、15 等值；主题偏好保存在 Share 与 Host 不同位置 |

| PWA | React / TypeScript / CSS；本地 IndexedDB 历史，网页节点连接 | 自有主题和布局；原生端嵌入完整网页时形成另一个应用，而非同一设备流程 |
| 公共规范与检查 | design-tokens.json、check-share-contract.py | 参数主要用于规范与局部字符串检查，尚未生成并约束各端实际组件；没有覆盖所有原生控件的视觉状态 |

Windows 主题问题还存在两个源码风险：新本机窗口没有统一的实时系统主题订阅；ThemeTree 递归改色无法完整覆盖控件模板及弹出内容，也容易把语义不同的文字统一刷成一个颜色。用户报告的具体白底白字控件仍需在 Windows 实际复现，不把源码推断写成已完成真机复现。

## 3. 建议的目标架构

### 产品壳、状态、服务分别负责什么

- 每个平台一个主应用壳，负责导航、页面保留、窗口尺寸和当前主题。
- 页面状态独立管理搜索、来源筛选、选中条目、设备状态、传输状态；页面只渲染状态、提交操作。
- 公共组件负责外观与操作状态，禁止页面重新发明按钮、设置行、搜索框和卡片。
- 应用服务负责剪贴板、历史仓库、分类、恢复与设备授权；界面不能各存一份历史或配对状态。
- 系统 / 网络适配器负责 Android 剪贴板、Windows 剪贴板、悬浮宿主、LAN 和节点协议。改页面不能改变设备身份和传输语义。

### 平台实现建议

| 平台 | 拟采用的实现 | 迁移边界 |
| --- | --- | --- |
| Android | Kotlin 原生 View + MVVM / 单向状态更新；统一主题资源与组件库 | 保留已验证的 WindowManager 宿主、吸附 / 收回运行时、存储与权限桥；拆除旧设备页 UI，抽取其连接服务。本轮不把全面迁移 Compose 作为前置条件 |
| Windows | 保留 .NET / WPF；XAML 页面 + MVVM + 统一 ResourceDictionary、ControlTemplate、DataTemplate | 一只主窗口承载剪贴板、设备、设置；托盘与快捷键留在系统服务层。移除原生 UI 中运行时拼接 XAML 的产品入口和递归刷色方式 |
| iPad PWA | 保留 React / TypeScript；相同页面结构、主题角色、数据和交互契约 | 布局按 iPad 调整；明确前台剪贴板与网页能力边界，不模拟系统浮窗或后台监听 |

保留 WPF 的理由是当前系统接口、托盘和数据存储已经在此实现；其样式、控件模板和数据模板可以集中定义一致外观。优先替换错误的组织方式和控件实现，避免同时重写全部平台服务。框架变更应作为独立决策，有原型与兼容证据后再讨论。

原生端不再把完整 PWA 当第二个主界面。LAN 与节点连接进入同一个设备流程；节点认证可有专用授权界面，认证后返回当前设备页。节点协议的原生适配工作单独列出、复用已有协议和测试向量，不自行修改加密方案。替代通道未达到功能和安全对等时，不删除旧实现，也不发布半迁移的产品入口。

建议目录责任：presentation/shell、presentation/pages、presentation/components、presentation/state、application、domain、platform、transport。三端共享协议与规范；具体源码按平台实现，不假设 Kotlin、C# 和 TypeScript 可以共用一份运行时代码。

## 4. 页面与导航布局

| 区域 | 手机 | Windows | iPad PWA |
| --- | --- | --- | --- |
| 剪贴板 | 单列正文卡片，顶部设备 / 设置，搜索与轻量来源筛选 | 一个主窗口；紧凑侧栏导航，主区同一剪贴板。查看全文后才出现详情面板 | 宽屏侧栏与列表，窄屏收为单列 |
| 浮窗 | 最近内容与必要筛选；固定模式连续取用。与主界面相同条目、主题和操作 | 保留托盘 / 快捷键调出；窗口行为独立于网络 | 不提供系统浮窗 |
| 设备 | 已授权设备列表、真实状态、一个添加入口 | 同一主窗口内切换，保留剪贴板状态 | 同样的设备语义，标明当前通道 |
| 添加设备 | 附近可达设备为默认；节点方式为选择步骤；身份确认后记住授权 | 相同流程，按鼠标 / 键盘调整 | 使用已实现且能到达的网页通道 |
| 设置 | 分组列表；外观、剪贴板与浮窗、权限与后台、数据、关于与更新 | 相同语义；权限 / 浮窗条目按平台替换；不另开一套设置应用 | 同样的分组，不展示平台不支持的开关 |

具体收敛：

1. 外观只保留一个入口。主题三选一、设备来源色、半透明表面都进入外观页，删除设置首页重复的主题切换。
2. 设备页删除常驻的巨型“iPad 与跨网设备”卡片及重复说明。网络方式是添加设备的步骤，不是另一套软件入口。
3. 连接状态以设备行呈现。离线、连接中、已连接、连接失败有明确区别；不能“尚未连接”与“已暂停”混在一起。
4. 共享操作从已有条目和设备详情发起；不恢复常驻聊天输入框、另一份收件箱或四个底部大栏目。
5. 手机一级页面保持紧凑头栏，二级页用相同返回按钮与标题基线；Windows 使用一个导航区域，避免不停开主功能窗口。
6. 分类在筛选或条目整理中出现；设备来源留在筛选和全文 / 操作详情。正文始终是卡片的主要视觉内容。

## 6. 主题与组件如何真正统一

- 每端只有一个 ThemeState：System / Light / Dark。主窗口、设备页、设置、浮窗、应用内菜单和弹层都订阅它；系统主题切换即时更新。
- 统一是同一设备内的应用一致，不强迫手机、Windows 和 iPad 同时采用同一亮暗模式；各自跟随各自系统。
- 参数由一份规范生成 Android 资源 / WPF 资源字典 / CSS 变量；页面使用语义角色，不在业务页面写十六进制主题色或随意的圆角值。
- 前景与背景成对绑定。WPF 使用完整模板覆盖 Button、Toggle、CheckBox、ComboBox 及弹出项、输入框、菜单、对话框和滚动条；删除递归改整棵可视树的 ThemeTree。
- Android 开关的轨道、滑块、选中、未选中、禁用全部由统一色表控制，避免蓝滑块配另一套绿色轨道。系统状态栏 / 导航栏随当前页面主题统一处理。
- 原生菜单 / 页面统一使用相同组件图源；操作提示按语义配色，不能给所有 TextBlock 一律写主文字色。
- 旧主题偏好只迁移一次：已有本机主界面明确选择优先；缺失时尝试旧共享页，再缺失则跟随系统。保留旧值用于诊断，不让两个配置反复覆盖。迁移规则需确认后实施。

## 9. 验收与发布阻断项

1. 白底白字、黑底黑字、文字与真实背景对比不足，任何页面 / 状态出现即阻断。
2. 同一设备跨页面主题分裂、切换主题后旧弹窗或下拉项不更新，即阻断。
3. 还存在旧共享页、完整 PWA 与新原生页平行组成的多套产品主入口，即阻断。
4. 同类按钮 / 开关 / 卡片的圆角、图标或字体不统一，或默认方形按钮混入自定义样式，即阻断。
5. 主界面、浮窗和设备收到的内容不在同一历史；复制改写来源；删除撤销丢元数据，即阻断。
6. 真实复制 → 历史 → 浮窗 → 粘贴闭环失败、收回抖动复发、搜索失焦、滑动误复制或误删除，即阻断。
7. Windows 在 100 / 125 / 150 / 200% 缩放、键盘 Tab / Enter / Escape、系统亮暗切换下出现遮挡或不可用，即阻断；视设备可用性提供可追溯证据。
8. 后台捕获、长期自动重连、节点与 LAN 的身份仍存在能力边界时，如实标明支持 / 受限 / 未实现，不能通过新 UI 把功能显示为已实现。
9. 自动化检查包含实际生成的组件和原生渲染 / 操作，不再仅用版本一致或色值出现在文件中判定通过。
10. 用户审阅仍有待确认或要求修改的项，发布门槛未通过。

## 11. 2026-10-21：设备剪贴板一级化与跨网入口收敛

用户已确认新的信息架构：共享设备的剪贴板不是弱来源标签，而是与“本机”同级的一等板块。首页和悬浮窗统一采用“全部 / 本机 / 已授权设备…”来源切换；来源是第一维导航，分类、搜索、置顶等继续作为第二维整理能力。数据仍只保存在统一 vault 中，以 sourceDeviceId / sourceDeviceName / sourcePlatform 区分，不能按设备复制多份历史。

已授权设备即使还没有收到第一条内容，也必须保留自己的来源入口。这一规则同时应用 Android 主界面、Android 悬浮窗和 Windows 本机窗口。当前实现新增 ClipboardSources，并让受信设备身份直接参与来源栏生成。

视觉以用户 02:12 提交的“设备”页为 Android 基线：浅灰页面背景、白色分组卡片、统一圆角和分隔线；蓝色只用于关键操作和选中状态。来源 / 分类的选中态统一为浅蓝表面 + 蓝色文字。悬浮窗保持更紧凑尺寸，但来源切换、圆角和选中语义与主 App 一致。

用户要求移除旧构建和早期连接诊断等不必要页面。产品边界调整为：
- Android 产品 manifest 不再注册旧 standalone ShareActivity 和 ProbeActivity。
- DeviceActivity 是手机端唯一设备管理产品入口。
- managed 设备页不再展示“连接帮助 / 网络诊断”入口。
- ShareActivity 源码暂只作为 DeviceActivity 内部布局基类和 nearby-probe 测试兼容层保留，不再作为用户可启动页面。
- 悬浮窗外观、主题、分类、备份恢复、权限后台、设备授权、更新和共享开关等核心能力全部保留。

iPad / 跨网能力保留，但不再作为另一套 FloatClip 产品壳。现有 Web / NativeBridge 已采用统一 source 模型并支持 android / windows / ipad / web 平台。目标是：
1. Android 设备页只保留“跨网设备（iPad / Web）”一行，与设备授权同卡。
2. 点击后进入 Node / Relay 授权管理；不把完整 PWA 作为 Android 第二个主界面。
3. iPad / Web 配对后获得稳定 device id，条目进入统一 vault。
4. iPad 与 Windows / Android 一样出现在首页和悬浮窗一级来源。
5. LAN、Bluetooth、Node/Relay 只属于同一设备关系下的不同 transport，不创建不同剪贴板 UI。
6. iPadOS/PWA 明确保留前台剪贴板能力边界，不伪装成 Android 式后台监听或系统浮窗。
