# 文件页交互修正：资源管理器式列表（2026-10-22）

> 2026-10-23 更新：已接入原生双端文件目录与按需传输，并构建 0.7.6 试用候选。下文记录预览阶段状态；当前实现、验证和未完成项见 [候选交接](CANDIDATE_0.7.6_2026-10-23.md)。

用户已基本认可 Fluent 主界面，但明确否定了电脑端上一版文件会话卡片：需要类似文件资源管理器“详细信息”视图的纵向文件清单，文件一直列在那里，按需下载传输。本轮完成修正后的交互预览，尚不发布客户端或修改 Android。旧的 floatclip-files-preview.html 中的电脑会话方案已被否定，不应据此实施电脑原生界面。最新反馈明确允许手机使用文件卡片，须保留时间戳和易点按的操作区，并适配原有配色和风格；不能把“电脑使用列表”理解为“手机也必须使用列表”。

## 设计

- 一个文件一行，默认列出名称、修改时间、类型、大小、来源、本机状态。小图标、紧凑行高、列头排序，不按发送者对齐，不显示会话气泡或消息时间线。
- PDF、Word、Excel 等有类型图标。图标状态以**当前设备**为准：本机已有为实心，未下载为虚线。默认只展示清单，选中、双击或右键都不会自动下载；只有显式“下载”或“下载并保存 / 转发”才模拟传输。
- 勾选多个文件后可批量下载，已在本机或源设备离线的条目不重复下载。取消后条目仍在清单中，可重新下载。来源设备离线时保留文件元信息，明确显示离线状态，不假定远端文件已经托管到云端。
- “预览 / 属性”展开同页详情栏，文件列表始终保留。较窄窗口将详情栏放到列表下方。PDF / Word / Excel 有示例内容；未下载时显示状态与明确下载按钮，离线时不可下载。
- 属性包含原始文件名、字节大小、原始创建 / 修改时间、下载时间、来源、本机位置，区分各类时间戳；另存为可以选择位置和重命名，转发可选设备。未下载文件必须显式确认“下载并保存 / 下载并转发”。
- 采用浅色、深色与东京夜色；可调整行高、图标大小及默认预览栏。文件大小 B / KB / MB 自适应，避免小文档显示 0.0 MB。320px 下隐藏次要列并在文件名下显示大小和来源，完整属性仍可打开。
- 选择用户本机文件时只读取名称、大小和修改时间等元信息，不读取文档内容；不为真实用户文件伪造内容预览。

## 已验证

浏览器验证：8 行初始文件清单；选中 / 预览不自动下载；按需单文件下载、取消 / 重试后保留条目、其他文件不跟随下载；多选批量下载、离线条目不下载、列头排序；PDF / Word / Excel 示例内容、原始修改时间、另存为改名、转发、真实文件仅元信息、Windows 文件名检查；东京夜色、580 / 390 / 320px 布局及无运行错误。脚本：.mcp/check-file-shelf.cjs；截图在 analysis/desktop-checks/file-shelf-*.png。

当前对话预览文件为 floatclip-file-shelf.html。示例文档、下载、保存和转发均为演示；没有真实网络收发、写入所选保存位置或向其他应用发送文件。添加文件只读取名称、大小、修改时间等元信息，未读取文件正文。列表状态为本次预览内存状态，未将用户文件名持久化到对话偏好。

- 电脑列表明确为文件名单元格、按钮、文本及文字填充指定产品文字颜色，避免依赖外层继承。东京夜色主文字改为 #e4e9ff，次要文字 #bbc4e5；浅色和普通深色也加强次要文字对比。预览表格同步指定前景色。保留蓝色强调，文件名不会随选中背景变为深色文字。
- 同样将文字对比调整落实到 Windows 原生 LocalClipboardWindow.Theme 的动态资源：东京夜色正文 #E4E9FF / 次要文字 #BBC4E5，普通深色次要文字 #BDC6D6，浅色次要文字 #5E6A7D。现有原生文件行已显式绑定 FloatClip.Text / Muted。修复现有 FileShelfView 的资源管理器参数引号语法错误以恢复整项目构建，未改动文件传输协议。
- 使用内置展示外壳验证浅色 / 深色 / 东京夜色的普通、悬停、选中、选中悬停状态：文件名最低对比 8.74:1，次要状态文字最低 4.78:1。脚本 .mcp/check-file-runtime-colors.cjs 检查实际计算颜色和文字填充色，弥补此前只检查窗口背景的不足；截图 file-shelf-runtime-colors.png。
- 手机单独预览：floatclip-mobile-file-cards.html。保持蓝色强调与圆角卡片，文件名两行、右侧类型图标、大小 / 下载状态，卡片上方常驻来源和共享时间，属性页保留原始创建 / 修改 / 下载时间。手机文件卡片不改变电脑列表方向。
- 每张卡片的整个内容区可点开预览；下方“下载 / 预览、另存为、更多”点击高度最低 48px，更多中有转发、属性和系统分享。未下载图标虚线、下载后实心；点卡片只打开详情，不自动下载。取消后保留文件信息。未下载文件的另存为 / 转发需明确“下载并保存 / 下载并转发”。

- 手机部分仍为设计交互示意，不代表 Android 客户端已修改或实际文件协议已接通。真实收发、持久化与 Office 解析限制继续适用。

## 原生接入注意

本轮交互获认可后，再落实 Windows 文件列表、文件元数据与状态模型、原生预览能力、保存对话框和转发流程。现有 ShareWire 是主动文件邀请与确认传输，只有文件名、大小和哈希，尚不支持持久远端清单与按需拉取。原生接入须新增可协商的共享文件目录（稳定标识、版本 / 哈希、来源、可用状态），显式请求后才传输文件内容，并处理撤回、源文件移动 / 删除 / 更新、离线重连和本机缓存失效；不能把当前推送邀请适配器当作目录已经完成。目录只包含用户主动共享的文件，不自动暴露整个设备文件系统。

创建 / 修改时间等跨端属性须新增可协商的元数据或明确标注未知，不能用接收时间冒充原始修改时间。清单与本机下载状态应持久化，源设备必须在线且文件仍可用才允许请求下载；本轮预览未实现这些真实持久化与协议能力。旧 Android 不支持该目录协议，保持现有文本同步兼容并通过能力协商回退；手机目录体验必须待 Android 后续适配，不在本次 Windows 独立预览中声称已支持。

PDF / Office 的真实内容预览仍需选定实现并验证旧 Windows 兼容性；不能将本轮示例页面当作原生解析器已完成。手机另存为/系统分享在本轮只是交互设计，Android 代码保持原状。原生文件传输适配的其他待办仍见 WINDOWS_FLUENT_REVIEW_2026-10-22.md。
