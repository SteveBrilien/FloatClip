# 设计系统变更记录

## 2026-10-23：0.7.8 / build 23 反馈修订

实施前差异：提示框继承的效果使文字发糊；文件表头仍有旧 Aero 高亮；工具栏 Hover 变化过弱；文件行还有类型字母色块；ZIP 预览仅放大关联图标；设备页嵌套多个展开器，并在开关更新时重建列表。

最小方案按共享组件先行：调整 Light/Tokyo Night 的 Hover/Pressed/SelectedHover；统一 ToolTip、ContextMenu/MenuItem、表头和设置行；图标与内容预览交给独立服务；设备页迁为 XAML + CommunityToolkit ViewModel，继续调用原生配对/同步服务。未引入其他 UI 框架或修改数据/协议。

本轮落地：提示框纯色无 Effect，manifest 声明 PerMonitorV2；表头取消 Aero 渐变；操作图标使用 Fluent System Icons；文件关联使用 Shell 原生高分辨率帧；容量统一 KB/MB/GB。ZIP 显示真实目录，Office 为只读文字/单元格，PDF 支持翻页。设备连接方式改为同级下拉选择；设备行原位更新，紧凑设置行容纳完整开关热区。设置页复用同一设置行，已打开辅助窗口的标题栏主题也同步。

Release / 自包含打包、168 项桌面检查（隐藏界面异常 0）与 43 项更新检查通过。两端签名更新主源与备用源实测 HTTP 200；Android 构建、61 项单测通过，lint 0 error / 17 warning。未把 0.7.8 推为公共更新。

用户负责本轮外观走查，不代替用户宣布视觉验收。四档真实 DPI/跨屏、蓝牙/手机实际往返、材质、全部既有页面 MVVM 仍未在本轮完成。验收矩阵和 Light/Dark 对比见 [0.7.8 候选记录](../CANDIDATE_0.7.8_2026-10-23.md)。

## 2026-10-23：从 0.7.7 WPF 基线收敛

### 实施前差异

- WPF UI 4.3.0 已提供基础模板，但页面覆盖了大量局部颜色/圆角/字号，悬浮反馈不一致。
- Light、Dark、Tokyo Night 有三份硬编码配色；字体、菜单和禁用状态缺少统一语义资源。
- 卡片缩放和滑动动画时长各自声明，缺少应用层“减少动画”。
- 视图主要以 C# 命令式创建，查询/清除逻辑与具体控件混在一起，尚未全面 MVVM。
- 材质仅做圆角和深色标题栏处理，Mica/Acrylic 的特殊悬浮窗验收未完成。
- 原回归覆盖功能与截图，未完成四档真实系统 DPI/跨屏交互验收。

### 本轮最小方案

先统一 XAML 设计资源、Light/Tokyo Night、基础控件状态、卡片反馈和 Motion Tokens；将剪贴板查询与清除迁入 ViewModel/服务，搜索视图迁入 XAML。保留宿主及数据格式。材质先做能力评估和纯色回退，未验收的悬浮窗口不启用系统材质。后续逐页迁出剩余命令式视图，不能把这一步描述为全面 MVVM 完成。

### 第一轮结果

共享 Tokens / Light / Tokyo Night / 基础状态已落地；XAML 搜索与 CommunityToolkit MVVM 查询/清除落地。菜单错误引用修复，隔离验收不再吞异常。Release 和自包含打包成功，146 项桌面 + 33 项更新检查通过，隐藏界面异常 0。正文、次要、禁用和主按钮状态文字的配色对比度均达到 4.5:1。

完整证据范围及未验收内容见 [本轮 WPF 验收记录](../WINDOWS_WPF_DESIGN_077_2026-10-23.md)。真实系统当前为 150%，四档离屏输出不能等同四档实机验收；Mica/Acrylic 不启用；全部页面 MVVM、字符图标迁移和真实设备回归未完成。
