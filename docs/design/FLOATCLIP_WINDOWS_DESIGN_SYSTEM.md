# FloatClip Windows UI 设计与工程规范

本文件是唯一设计规范。所有 UI 改动服从此规范，不得让规范迁就页面的新实现。核心目标是在保持现有功能和数据兼容性的前提下，实现统一、成熟、稳重、原生感强且反馈明确的 Windows 11 Fluent 风格应用。Fluent 2 是视觉与交互参考，不是 WPF API 文档。

## 1. 唯一设计系统

- 维护唯一的 FloatClip Design System，统一颜色、字体、圆角、间距、图标、阴影、透明度、动画和控件状态。
- 视觉属性优先引用 Design Tokens；页面不得任意新增硬编码颜色、圆角、阴影或动画值。
- 已有组件满足需求时必须复用，不创建外观相似而实现不同的组件。
- 各页保持同一风格，不直接混用多个 UI 框架的默认主题。

## 2. 架构与依赖

- 保留 WPF + XAML，不因外观优化迁移 WinUI 3、WebView 或其他 UI 框架。
- 修改前检查 .NET、主题库和依赖，再决定使用 WPF UI 或内置 Fluent。本轮基线：.NET 10、WPF UI 4.3.0、Emoji.Wpf 0.3.4；继续使用 WPF UI，不同时加载内置 Fluent 默认主题。
- MVVM 分离 View、ViewModel、Model、Service，优先 CommunityToolkit.Mvvm。
- XAML 承担视图结构、样式与状态；业务逻辑不能依赖具体控件。既有代码视图逐步迁出，禁止为局部优化重写全部页面。
- 剪贴板、窗口管理、设备同步独立为服务。重构保留数据、配置、配对、加密协议与原功能兼容性。

## 3. 视觉

- Light：Windows 11 中性 Fluent；Dark：统一 Tokyo Night。旧 `tokyo-night` 设置继续兼容；深色不再另设不同的配色体系。
- 只能使用语义资源：Background、Surface、TextPrimary、TextSecondary、Border、Accent、Danger、Hover、Pressed 等；状态色和文件类型色也统一入资源。
- 间距以 4 DIP 为基准，优先 4/8/12/16/24/32；圆角使用 4/8/12/16 DIP 分级。
- 统一字体族、字号梯度、字重、行高与截断策略。正文必须支持中文、英文、Emoji、长文本及换行。
- 图标优先 Fluent System Icons，统一 16/20/24 DIP 图标及热区/基线。品牌资产、文件关联图标和用户内容中的 Emoji 为有明确语义的例外；不把字符或 Emoji 当作新增操作图标。
- 文件行优先取 Windows Shell 的实际文件/扩展名关联图标，保留原生高分辨率帧；不把 16px 图标强行放大，也不以手绘“ZIP/W/X”文本色块替代系统关联。Shell 图标未必是矢量，不能声称所有第三方关联图标都能无限缩放。
- 面向用户的文件容量统一显示 KB/MB/GB，采用 1024 阶梯；不足 1 KB 显示 `< 1 KB`，零长度显示 `0 KB`。精确字节数继续用于传输与校验。
- 分类名称复用 vault 字段；分类列表与特征色由独立服务统一提供。右键必须能选已有分类，设置可以修改语义特征色，不为每个名称新增硬编码 Brush。
- 禁止白底白字、深底深字、对比度不足或无意义装饰。

## 4. 材质

- 主窗口优先评估 Mica；临时菜单/轻弹层可评估 Acrylic；普通卡片与密集数据区使用 Solid Surface。
- 系统版本、DWM 合成、高对比度和系统透明效果必须检测；不满足条件时可靠回退纯色。
- 窗口透明度、局部透明度、材质强度由统一配置服务控制。
- 特殊悬浮窗的置顶、点击穿透、焦点、性能和材质兼容未验证前，保持纯色，不以开启一个 API 当作材质验收通过。
- 纯色为默认。可主动选择的磨砂/透明模式只改变背景，正文与普通卡片保持不透明；密集文件/设置页使用纯色。窗口类型切换应只重建界面，保持后台宿主、数据、配对与当前页面；不能用整体 Window.Opacity 把文字一并变淡。材质需记录实际验证范围，未经验证的系统/硬件保留回退。

仅背景透明继续保留前景不透明。用户主动选择“整窗透明”时，允许文字、图标和图片一起变淡；使用普通 HWND 与 SetLayeredWindowAttributes，不启用 WPF AllowsTransparency。背景/主题/页面刷新不得反复设置整体 Opacity，防止覆盖外部工具调整。两种窗口类型切换仅替换界面窗口，不重启应用后台。设置说明保持简短，普通标题单行截断，窄内容区将控件放到标题下一行，防止展开导航后把卡片撑高。不得在 WPF 逐像素窗口上混用这两类分层 API。

## 5. 动效

- 统一 Motion Tokens：Press 100 ms，State 160 ms，Panel 240 ms；EaseOut 或 EaseInOut。
- 按压可轻微缩放，不能改变布局。悬浮球、卡片进入、菜单和面板遵循同一视觉语言。
- 快速操作需取消/替换旧动画，禁止重复播放、抽搐、状态错乱或动画遮挡热区。
- 复制成功后提供“已复制”确认，失败不得显示成功。界面刷新不能提前重建卡片吞掉按压/释放动画；仅允许短暂合并视图刷新，不延迟数据保存或设备同步。提示停留时长独立于减少动画开关。
- 尊重系统动画设置、高对比度及应用“减少动画”，正常降级为即时状态。

## 6. 组件与窗口

- Button、ToggleSwitch、TextBox、ComboBox、Slider、ContextMenu、Dialog、Card、NavigationItem 统一资源和行为。
- 覆盖 Normal、Hover、Pressed、Focused、Disabled；适用时覆盖 Selected、Loading、Error。
- 设置、剪贴板、设备、搜索、二级菜单和通知统一结构；无重复返回、冗余标题/解释和重复入口。
- 普通设置和辅助窗口默认非模态；仅确需决策时使用模态。
- 定义弹层关闭、失焦、层级、滚动、焦点和键盘规则。搜索框外部点击须释放焦点；“全部清除”无撤销，固定/置顶记录保留。
- 提示框使用纯色 Surface、共享边框、字号与布局取整；避免使文字光栅化变糊的 Effect/缩放。不把阴影当作悬停反馈，按钮/行应直接使用 Hover/Pressed 语义色。
- 文件预览必须显示实际内容，且默认非模态。图片/PDF、压缩包目录、Office 文字/单元格须明确预览范围；不支持时禁用预览或说明范围，不允许用放大的文件图标冒充内容。
- 设备页复用设置行，蓝牙和局域网作为同级选择，仅显示选定连接方式的步骤。同步开关更新属性，不重建整个设备列表；保留设备行实例、滚动位置和稳定热区。
- 文件行模板的 Normal/Hover/Selected 使用纯色语义面，禁止继承系统默认渐变叠层。保留 GridView 列对齐、列宽调整、多选及单独焦点轮廓。连接状态须区分文字同步和可共享文件的会话，不能把蓝牙就绪表述为文件已共享。

## 7. 响应与兼容

- 使用 WPF DIP，不依赖固定物理像素；分别覆盖紧凑、正常和最大化布局。
- 验证 100%、125%、150%、200% DPI 的显示与热区。离屏渲染不能冒充实际系统缩放与跨屏验收。
- 避免不必要的横向滚动、裁切和固定宽度溢出。确实无法容纳的详细文件表格在自身滚动区处理，不强制改变窗口宽度。
- 切换主题覆盖全部窗口、弹层和交互状态。

## 8. 每次修改流程

1. 阅读规范、组件库、相关页面，确认可复用内容。
2. 列出实现差异。
3. 提出最小必要方案，不因局部优化重写整个 UI。
4. 先改共享资源和组件，再改业务页面。
5. 编译、静态检查、功能测试和可行的视觉检查。
6. 对比 Light/Dark 前后截图与交互。
7. 检查重复 Style、ControlTemplate、Brush 与新增第三方 UI 依赖。
8. 更新规范、差异清单、变更记录和未验收事项。

## 9. 每次交付报告

- 设计一致性：颜色、间距、圆角、字体、图标、材质。
- 行为一致性：悬停、按压、滑动、弹层、窗口焦点。
- 主题完整性：Light、Dark、切换覆盖。
- 兼容性：DPI、窗口尺寸、长文本、Emoji。
- 功能回归：剪贴板、固定/置顶、搜索、清除、同步。
- 构建：成功、失败或未验证，必须如实描述。

未经验证不得声称视觉或功能验收完成；“已统一规范”不等于“全部页面已迁移”。
