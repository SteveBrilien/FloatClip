# FloatClip Android build56 response to field reports

1. Update: `native-updates-v2` is still JWS-signed build50. A candidate Release does **not** update that feed. `checkLatest()` preserves JWS verification for the production channel, then checks the official GitHub repository's candidate Releases. Candidate discovery uses an exact versioned asset URL, SHA256 release digest and size. The existing `ClientUpdateInstaller` still verifies the downloaded APK's SHA256, app package ID, version and pinned installed-app signing certificate before offering installation. A malformed signed JWS aborts candidate lookup. Existing build55 cannot discover newer candidates until upgraded to build56 or the original signed update feed is republished with the existing private key (stored on the offline Windows PC).
2. Text: in-place overlay now uses the floating panel's palette rather than black; long text retains native ScrollView vertical dragging and selection. Horizontal gestures change entries in the same category, vertical gestures at a long document's top/bottom boundary change categories. Swipe navigation is inhibited for long-press selection and multi-touch.
3. Devices: the legacy ShareActivity used system dark palette for a `hostTheme()` value of `klein` (ignored). Apply the same Klein color tokens used in the native app.
4. Image viewport: fit-center uses min(viewWidth/imageWidth, viewHeight/imageHeight) regardless of image orientation. Double-tap and pinch retain deliberate zoom; not height-fill cropping.
5. Photo import: for regular EXIF-normal JPEG retain original bytes and full dimensions in private app storage without a PNG roundtrip; EXIF-rotated or oversized photos normalize once to high-quality JPEG. PNG screenshots are preserved byte-for-byte. The thumbnail cache remains separately compressed/encrypted, viewer reads original JPEG through region decode, and a bounded PNG is encoded only for peers speaking the existing PNG transfer protocol. Android image metadata and `ClipboardImageProvider` distinguish JPEG/PNG. New image blob files are plaintext only within app-private storage, with legacy encrypted PNG readable. **Downgrade risk:** prior APKs do not understand JPEG blobs or the new plaintext image-file format; backup before installing and do not downgrade without migration.

## Device acceptance

User phone ADB/Remote currently offline. Worktree and automated tests cover code paths, not on-device gestural feel, OEM dialogs, gallery I/O timings, frame pacing, large panorama imports or power consumption. No user data has been overwritten, and no production update signing key was rotated.
